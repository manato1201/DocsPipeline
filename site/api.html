API リファレンス¶

docstring から自動生成する。直接編集せず、コードの docstring を直すこと。

docstring から API 文書を作り、Confluence へ公開するための共通設定と CLI。

各リポジトリの docs/conf.py から読み込む共通の Sphinx 設定。

使い方 (docs/conf.py):

from docspipeline.config import build_config

globals().update(
    build_config(
        confdir=__file__,
        project="ProfilingTool",
        author="manato1201",
        package_paths=["../src"],
    )
)

個別のリポジトリが決めるのは名前と対象のパスだけで、拡張・autodoc・Markdown 取り込み・ Confluence の設定はここに集める。

docspipeline.config.build_config(*, confdir, project, author, release='', language='ja', package_paths=None, mock_imports=None, use_hou_stub=False, cpp_sources=None, cpp_predefined=None, license_note='', extra_extensions=None)¶

Sphinx の設定を辞書で返す。

パラメータ:

  • confdir (str | Path) -- conf.py の場所。__file__ をそのまま渡してよい。

  • project (str) -- 文書の題名 (プロジェクト名)。

  • author (str) -- 著作者名。

  • release (str) -- バージョン表記。

  • language (str) -- 文書の言語。

  • package_paths (list[str | Path] | None) -- autodoc が import できるようにする Python のソースの場所 (confdir からの相対パス)。

  • mock_imports (list[str] | None) -- autodoc のときだけ偽物に差し替えるモジュール名。

  • use_hou_stub (bool) -- Houdini の hou が無い環境用のスタブを使うか。 本物の hou が import できる環境では、そちらが優先される。

  • cpp_sources (list[str | Path] | None) -- Doxygen に読ませる C++ のソースの場所 (confdir からの相対パス)。 指定すると Breathe と docspipeline.doxygen を有効にする。

  • cpp_predefined (list[str] | None) -- Doxygen のマクロ定義 (PREDEFINED)。

  • license_note (str) -- 出典・ライセンスの注記。HTML のフッターと Confluence の各ページ末尾に固定する。

  • extra_extensions (list[str] | None) -- 追加の Sphinx 拡張。

戻り値:

conf.py の名前空間へ update する設定の辞書。

戻り値の型:

dict[str, Any]

Confluence 公開まわりの設定と安全装置。

公開の設定は環境変数から読む。API トークンを設定ファイル・ログ・文書に残さないための 方針で、このモジュールはトークンの値を保持するだけでなく、出力から伏せる処理 (mask_secrets()) も持つ。

公開には 3 つのモードがある。既定は local で、ネットワークには一切つながない。

local

Confluence 形式の出力をローカルに作るだけ (公開しない)。

dryrun

Confluence に接続して、何が作成・更新されるかを確認する。ページは変更しない。

publish

親ページ配下へ実際に公開する。

docspipeline.confluence.REQUIRED_ENV = ('CONFLUENCE_SERVER_URL', 'CONFLUENCE_SPACE_KEY', 'CONFLUENCE_PARENT_PAGE', 'CONFLUENCE_SERVER_USER', 'CONFLUENCE_API_TOKEN')¶

dryrun / publish で必須の環境変数。値は出力に出さず、名前だけを報告する。

docspipeline.confluence.SECRET_ENV = ('CONFLUENCE_API_TOKEN',)¶

値を伏せる対象の環境変数。

exception docspipeline.confluence.ConfluenceSettingsError¶

ベースクラス: Exception

Confluence の設定が足りない、または安全でないときの例外。

mmdc (mermaid-cli) の探索と実行。Sphinx に依存しない。

docspipeline.mermaid (Sphinx 拡張) と、docspipeline.doctor (環境の確認) の両方が使う。 Sphinx が入っていない環境でも docspipeline の各コマンドが動くように、拡張の側 (Sphinx を import する) とは別のモジュールにしている。

docspipeline.mmdc.THEME_VARIABLES = {'clusterBkg': '#f2f4f7', 'clusterBorder': '#d0d5dd', 'edgeLabelBackground': '#ffffff', 'fontFamily': 'Noto Sans JP, Hiragino Sans, Meiryo, sans-serif', 'lineColor': '#667085', 'primaryBorderColor': '#d0d5dd', 'primaryColor': '#ffffff', 'primaryTextColor': '#101828'}¶

図の色とフォント。GitHub (Markdown のまま表示) と、Sphinx (mmdc で SVG にした HTML) の 両方で、同じ見た目にするための値。色はこのリポジトリの構成図 (diagrams.net) と揃えてある。

docspipeline.mmdc.FLOWCHART_CONFIG = {'nodeSpacing': 40, 'padding': 14, 'rankSpacing': 56, 'wrappingWidth': 480}¶

流れ図の設定。wrappingWidth を大きくしないと、日本語の長い行が、単語の途中で折り返される。

docspipeline.mmdc.SEQUENCE_CONFIG = {'actorMargin': 30, 'messageMargin': 34, 'mirrorActors': False, 'width': 150, 'wrap': False}¶

順序図の設定。下に同じ参加者を繰り返さず (mirrorActors)、横幅を詰めて、文字が小さくならないようにする。

docspipeline.mmdc.MERMAID_INIT = '%%{init: {"theme":"base","fontFamily":"Noto Sans JP, Hiragino Sans, Meiryo, sans-serif","themeVariables":{"fontFamily":"Noto Sans JP, Hiragino Sans, Meiryo, sans-serif","primaryColor":"#ffffff","primaryBorderColor":"#d0d5dd","primaryTextColor":"#101828","lineColor":"#667085","clusterBkg":"#f2f4f7","clusterBorder":"#d0d5dd","edgeLabelBackground":"#ffffff"},"flowchart":{"wrappingWidth":480,"nodeSpacing":40,"rankSpacing":56,"padding":14},"sequence":{"mirrorActors":false,"wrap":false,"width":150,"actorMargin":30,"messageMargin":34}}}%%'¶

各 Mermaid ブロックの 1 行目に置く、標準の初期化の行 (%%{init: ...}%%)。 GitHub は、この行から色とフォントを読む。docspipeline check-mermaid が、全ブロックにあるかを確かめる。

docspipeline.mmdc.MERMAID_CLASSDEFS = '    classDef input fill:#dae8fc,stroke:#1a73e8,color:#101828\n    classDef proc fill:#e6f4f1,stroke:#0f9d8a,color:#101828\n    classDef out fill:#fff7ed,stroke:#e8710a,color:#101828\n    classDef stop fill:#fef3f2,stroke:#d92d20,color:#101828\n    classDef plain fill:#ffffff,stroke:#d0d5dd,color:#101828'¶

図の部品に色を付ける classDef の標準の組。入力 = 青、Sphinx・処理 = 緑、出力・公開 = オレンジ、 止まる・失敗 = 赤、補助 = 白。ブロックの末尾に貼って使う。

docspipeline.mmdc.MERMAID_CONFIG = {'flowchart': {'htmlLabels': False, 'nodeSpacing': 40, 'padding': 14, 'rankSpacing': 56, 'wrappingWidth': 480}, 'fontFamily': 'Noto Sans JP, Hiragino Sans, Meiryo, sans-serif', 'htmlLabels': False, 'sequence': {'actorMargin': 30, 'messageMargin': 34, 'mirrorActors': False, 'width': 150, 'wrap': False}, 'theme': 'base', 'themeVariables': {'clusterBkg': '#f2f4f7', 'clusterBorder': '#d0d5dd', 'edgeLabelBackground': '#ffffff', 'fontFamily': 'Noto Sans JP, Hiragino Sans, Meiryo, sans-serif', 'lineColor': '#667085', 'primaryBorderColor': '#d0d5dd', 'primaryColor': '#ffffff', 'primaryTextColor': '#101828'}}¶

mmdc に渡す設定。文字を HTML (foreignObject) ではなく SVG の <text> で描かせる。 foreignObject は SVG を画像として取り込む先 (Confluence など) で文字が消えることがある。 図に %%{init}%% が無くても、同じ見た目になるよう、色とフォントもここに入れる。

Mermaid の図をビルド時に画像 (SVG) へ変換する Sphinx 拡張。

Confluence では Mermaid がそのまま描画されない可能性がある。このため HTML でも Confluence でも、同じ画像を取り込む。変換には mermaid-cli (mmdc) を使う。

literal

warn

警告を出したうえで、コードをそのまま表示する。

error

ビルドを失敗させる (CI 用)。

Sphinx のビルド開始時に Doxygen を走らせて XML を作る拡張。

C++ の文書は Doxygen が XML にし、Breathe が Sphinx へ取り込む。この拡張は、その前段 (Doxygen の実行) を sphinx-build の中に閉じ込めて、別の手順を覚えなくて済むようにする。

Doxygen が出す警告 (コメントの書式の誤りなど) は Sphinx の警告として転送するので、 -W で CI を止められる。

Doxygen が手元に無い環境では、環境変数 DOCSPIPELINE_SKIP_DOXYGEN=1 で飛ばせる。 その場合、Breathe の指示子が「XML が無い」という警告を出す。-W ではビルドが失敗するので、 手元で C++ 以外を確認したいときは docspipeline build --no-strict と組み合わせる。

docspipeline.doxygen.setup(app)¶

Sphinx 拡張の登録。

パラメータ:

app (Sphinx)

戻り値の型:

dict[str, Any]

手順に添える「プロンプトのコピー」ブロック (.. prompt::)。

手順の説明に、そのまま Claude Code に渡せるプロンプトを載せ、HTML ではコピーボタンを付ける。 読む人は、手順を自分で言い直さずに、そのまま貼り付けられる。

使い方 (reStructuredText):

.. prompt:: 新しいリポジトリに docs/ を作る

   このリポジトリに DocsPipeline で docs/ を作ってください。
   docspipeline init と docspipeline build を実行し、警告が出たら原因を直してください。

Markdown (MyST) では:

```{prompt} 新しいリポジトリに docs/ を作る
このリポジトリに ...
```

出力:

  • HTML: 題名・本文・「プロンプトをコピー」ボタン。ボタンは JavaScript で足す (JavaScript が無くても、本文は読めて、選択してコピーできる)。

  • Confluence などの HTML 以外: 題名と、普通のコードブロック。ボタンは出ない。

プロンプトに 秘密情報を入れない。トークンやパスワードらしき値 (API_TOKEN=abcdef123456 の形) が 含まれていると、警告を出す。-W ならビルドが失敗する。

docspipeline.prompt.SECRET_PATTERN = re.compile('(?:TOKEN|SECRET|PASSWORD|PASSWD|API_?KEY)\\w*\\s*[=:]\\s*[\'\\"]?(?![<$.])[^\\s\'\\"<>$]{8,}', re.IGNORECASE)¶

秘密情報らしき 名前=値 の形。名前に TOKEN / SECRET / PASSWORD / API_KEY を含み、値が 8 文字以上。 値の例 (<値>・$変数・...) は、除く。

docstring が無い公開 API の一覧 (カバレッジの確認)。

Sphinx の autodoc は docstring が無い項目を黙って飛ばすので、-W でも気づけない。 このモジュールはソースを構文解析 (ast) して、公開 API のうち docstring が無いものを数える。 コードは import しない。副作用のあるモジュールや、hou のように環境が要るモジュールでも安全に使える。

公開 API とは、次のものをいう。

  • _ で始まらない名前のモジュール・クラス・関数・メソッド

  • モジュールに __all__ があるときは、そこに載っている名前だけ

@overload と、プロパティの setter / deleter は数えない (docstring を書く場所ではないため)。

ソースを構文解析して作る、パッケージの構造の地図 (docspipeline map)。

コードを import せずに ast だけで読み、モジュールどうしの依存を取り出す。 結果は「機械的な地図」で、次の三つに使う。

  • アーキテクチャ文書の下書き: モジュールの一覧と依存の図を Markdown で出す。 推定を含むので、人が確認してから使う。そのまま公開しない。

  • 依存の向きの点検: 循環していないか、あるべきでない依存が無いか。

  • 手書きの図とのずれの検出: 構成図が、実際の依存と一致しているか。

外部へは何も送信しない (ローカルの読み取りだけ)。

見つける依存は 2 種類。

import

import 文による依存 (相対 import を含む)。

reference

モジュールの名前と 完全に一致する文字列 による参照 (Sphinx の extensions = ["pkg.ext"] のような、名前での読み込み)。

import は、モジュールを読み込んだときに実行されるものだけ。次の 2 つは、実行時の循環にならないので、 別に扱う (循環の検出の対象にしない)。

  • if TYPE_CHECKING: の中の import (型検査のときだけ)。依存として数えない。

  • 関数の中の import (deferred)。呼ばれたときに初めて読み込まれる。循環を断つ定番の書き方。

見つけられないもの: importlib.import_module(変数) のような動的な読み込み、部分的に組み立てた名前。
